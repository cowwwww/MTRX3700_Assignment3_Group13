# MTRX3700 V2_BOARD — 物理上板集成

本目录由 V1 复制建立，原 V1 不修改。入口是 **board/quartus/robot_board.qpf**，顶层 **robot_board**，设备 **5CSEMA5F31C6 / DE1-SoC**。根目录旧 README、quartus/ 及旧 evidence 保留作历史参考；本版本状态以本文、docs/V2_STATUS_ZH.md 和 docs/evidence/board/ 为准。

## 编译、下载

1. 双击 `board/quartus/robot_board.qpf`，用 Quartus Prime Lite 18.1 打开。检查顶层为 robot_board；不要打开旧的 quartus/robot_system.qpf。
2. Processing → Start Compilation（Ctrl+L）。检查 Errors 和 TimeQuest 时序报告，不能仅根据生成了 SOF 判断时序合格。
3. 文件是 `board/quartus/output_files/robot_board.sof`。打开 Tools → Programmer；Hardware Setup 选择 USB-Blaster，模式 JTAG。
4. Auto Detect 后选择 Cyclone V 的 FPGA 项，Add/Change File 指向该 SOF，勾选 Program/Configure，点击 Start。不要选择 HPS 项，不需要烧写 JIC。
5. SOF 是临时配置，断电丢失。本工程未自动连接或烧录任何硬件。

首次测试先用同级 `HWTEST_2026/prebuilt/hwtest.sof` 按官方指南检查硬件，再换 V2。官方自测的遥控器操作和 V2 不同。

## 接线和控制

沿用官方 2026 转接板接线，不需手工重新指定引脚。前向超声波必须接 **J3（TRIG GPIO_1[27]，ECHO [29]）**；V2 不使用其他超声波。底盘 UART：**GPIO_1[31] → 底盘 RX**，115200、8N1、共地。Nano 的 GPIO_1[3]/[5] 是另一条 UART；V2 目前没有 WiFi/Nano 回显功能，不能用 Nano UART 替代底盘连线。

| 控制 | V2 行为 |
|---|---|
| SW9=0 | 总禁止，持续停车；启动时保持 0 |
| SW9=1 | 允许后续人工解除停车，不会单独启动 |
| KEY0 | 复位视觉/导航/传感器/Nano；底盘发送器继续发零速度 |
| KEY1 或遥控数字 1（0x01） | 锁存停车 |
| KEY2 或遥控数字 2（0x02） | 解除锁存停车；仍须相机、距离、线路均有效 |
| SW0=1 / 0 | 基础跟线 / 三行曲率跟线 |
| SW8=0 / 1 | 暗线 / 亮线；阈值固定 96，需要现场核对 |
| SW7:4 | 数码管调试页（见下表） |

遥控数字 1/2 的代码沿用官方遥控器；KEY 按键可独立测试。松开 STOP 不会自动清除锁存。障碍物消失/线路恢复则属于导航暂时禁止：在已解除锁存的情况下，连续 3 个可用帧后允许自动恢复，测试人员应预期这一行为。

轮速抽象值 ±255 映射为最大 ±0.100 m/s；基础直线速度 96 对应约 0.037 m/s。它是报文目标值，实际轮速、左右方向及低速是否能起转必须架空轮子验证。正常报文周期 200 ms。停车中途不截断 JSON，完成正在发送的报文后立即发送零速度；之后继续零速度心跳。板子掉电或拔掉串口，FPGA 无法发送停车，底盘自身超时行为按官方自测说明检查。

## 数码管和 LED

HEX5 为最左高位，HEX0 为最右低位，所有数字为十六进制。

| SW7:4 数值 | HEX5..HEX0 |
|---|---|
| 0（默认） | 距离 mm 的 3 位 HEX + 最近遥控码 2 位 + 导航状态 1 位 |
| 1 / 2 | 累计图像位移 X / Y 的低 24 位；有符号补码 |
| 3 | 单次 dx 8 位、dy 8 位、状态 flags 8 位 |
| 4 | best SAD 16 位 + contrast 8 位 |
| 5 | reference ID 低 12 位 + current ID 低 12 位 |
| 6 | second SAD 16 位 + flags 8 位 |
| 7 | 丢帧计数 16 位 + flags 8 位 |
| 8 | 累计 X 高 8 位、累计 Y 高 8 位、flags 8 位 |

flags 位 7..0：保留、accepted、rejected、tracking_valid、continuity_lost、overflow、搜索边界、match_valid。调试数据是最近一次发布的快照；没有新结果时显示可能保留旧值，不可用它单独断言相机还活着。累计位移单位为 **像素**，丢帧后不代表完整运动轨迹，尚无毫米标定、机器人位置估计或位姿反馈导航。

导航状态：0 INIT，1 BASIC，2 ADVANCED，3 LINE_LOST，4 SENSOR_FAULT，5 OBSTACLE_STOP，6 E_STOP。

LEDR[0] 相机配置成功；[1] 帧结束翻转；[2] 最近帧良好；[3] 锁存停车；[4] 允许底盘命令；[5] 已解除锁存；[6] 最近距离样本有效；[7] 障碍停车；[8] CDC 故障；[9] SW9。LED2/6 是最近样本状态，不能表示数据仍新鲜，超时看导航状态。

## 最小实体测试顺序

按顺序填写 `docs/V2_HARDWARE_TEST_RECORD.csv`，尚未实测的项不得填写 PASS。

1. **固定和接线**：断电安装 FPGA、相机和转接板，确认绝缘、线缆有余量且不卷轮；先将轮子架空。拍照记录高度、俯角及端口。
2. **官方自测**：用官方 SOF 分别验证 VGA/相机、J3 超声波、底盘串口和遥控；记录实际遥控码与轮子方向。自测不通过先修硬件。
3. **V2 静止启动**：SW 全 0 下载 V2；预期轮子不转，LEDR0 在相机配置后亮，LEDR1 随帧变化，VGA 灰度图稳定，HEX0=6。连续 3 次复位应保持停车。
4. **距离测试**：SW9 仍为 0；对准平面目标，在 100/200/500 mm 记录 HEX5..3（转换为十进制），每处 5 次。无回波可能输出 4000（0xFA0），它是远距离哨兵，不是精确测量。断开 ECHO 的测试在断电改线后进行，随后检查无法运行。
5. **架空使能**：摄像头看到完整测试线、前方目标远于 240 mm；SW0=1、SW9=1，按 KEY2。满足连续 3 个远距离样本和连续 3 个可用图像帧条件后 HEX0=1，确认左右轮向前；失败立即 KEY1。检查遥控 1 停、遥控 2 解除，分别重复 5 次。
6. **停车覆盖**：轮子运行时依次 KEY1、遥控 1、SW9=0、按住 KEY0；每项都记录轮子实际停止延迟。释放按钮不会自行清除锁存；KEY0 松开后仍须重新解除。
7. **线路/障碍保护**：已解除停车时遮挡相机、移走线、放入近于 180 mm 的障碍物。应进入状态 3/5；近距离边界及恢复点以距离保护参数为准。恢复线或移走障碍后会重新积累 3 帧再运行。测试时轮子保持架空。
8. **低速地面跟线**：确认轮向和停止可控后，用直线→缓弯→不同灯光顺序测试。先基础模式，再三行模式；记录脱线次数、偏离量、是否振荡。相机俯角、线宽、阈值调整均记入记录。
9. **图像位移**：SW9=0，使用有纹理静止平面，页 3 看静止 dx/dy，缓慢平移相机/地面纹理看方向；页 4/6 看匹配质量；过快移动触及 ±4 搜索边界应拒绝。连续性丢失后累计值不再是完整位移。此项验证图像算法，不是机器人里程计精度验收。
10. **持续与重新上电**：运行至少 5 分钟，观察 VGA、距离、跟线和停车；重复上电 3 次，必须从停车状态开始。保存视频、配置、SOF SHA256 及所有失败现象。

仿真入口 `board/tools/run_board_checks.py`（本机原生工具路径可用 MTRX_DEPS 覆盖）及原有 `tools/run_tests.py`。本地 Verilator 版本若不为课程要求版本，只能作为开发验证，不能替代指定环境验收。
